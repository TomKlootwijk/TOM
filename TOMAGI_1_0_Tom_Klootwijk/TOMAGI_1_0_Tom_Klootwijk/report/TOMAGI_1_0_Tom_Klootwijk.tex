\section*{Abstract}
The supplied project corpus repeatedly combines a one-bit parity/jitter signal, a log-encoded polar look-up table, lower-case $\phi$, second-order kinematics, an analytic cone and its circle/pyramid/sphere projections, a binary branch structure, an L-system, signed-distance-zero language and a Klein-bottle-style topology. Later source documents add content-addressed definitions, explicit operation order, a 20/18/14/12 key, portable GPU records, zero-based timeline semantics, overlap lenses, active-bit/pulse geometry and a query-first state/transition/lineage interpretation.

This report condenses those pieces into one executable engine: \textbf{TOMAGI}, the \emph{Topological Operator Machine for Analytic Geometric Inference}. The authoritative state is a 64-byte integer record. The authoritative instruction/data object is a 48-byte LUT cell. A canonical 64-bit log-polar key selects a defined cell; defined cells are literally the SDF-zero set. A deterministic parity-of-mixed-word bit applies a bipolar perturbation and selects one of two successors. The same state then passes through integer change-of-change kinematics, lower-case-$\phi$ and timeline updates, reflective Klein or half-turn transport, branch-indexed hinge/radix routing, a chirality-aware L-system step, cone/sphere relations and downstream projection/emission. Emission returns a symbolic output and a deterministic replay lineage. Generic content-addressed definitions can authenticate that trace, select records, project integer fields and format SVG, OBJ or CSV bytes at compile time; materialization only replays the lowered bytes.

The package executes the same binary program on a dependency-free Python oracle and a portable C99 evaluator. It also supplies integer-equivalent GLSL, WGSL and OpenCL kernels. The implemented claim is exact and finite: when a knowledge or control domain is compiled into literal definitions, relations, branches and output tokens, TOMAGI replaces learned prediction with deterministic operator execution.

\begin{decisionbox}
TOMAGI is the engine, not merely an image format, neural network, probabilistic model or vendor-specific accelerator. Its core is a content-addressed, fixed-width state machine whose memory cell is simultaneously a definition, an operator and a zero-level relation. The generic host boundary evaluates representation-agnostic definitions during compilation and later concatenates literal \code{EMIT} byte chunks; it has no artifact-format, shape or dimensional vocabulary.
\end{decisionbox}

\section{The TOMAGI program object}

\subsection{Definitions, cells and state}
A TOMAGI program is
\begin{equation}
P=(\mathcal{D},C,i_0,s,m_0,q_0,F),
\end{equation}
where $\mathcal{D}$ is a content-addressed definition registry; $C=(c_0,\ldots,c_{N-1})$ is a strictly key-sorted cell table; $i_0$ is the entry index; $s$ is a deterministic seed; $m_0$ is the default transition horizon; $q_0$ is the initial state; and $F$ is the program profile word.

A literal definition node is
\begin{equation}
d=(id,kind,A,B,\vartheta,Dep,phase,prov,h),
\qquad
h=\operatorname{SHA256}(\operatorname{canonicalJSON}(d\setminus\{h\})).
\end{equation}
Every dependency ID must resolve and the finite definition graph must admit a topological order. This establishes one meaning for the literal program before execution.

A \code{tomagi\_cell\_operation} definition owns opcode, flags, arguments, successors, payload and auxiliary value. A source cell may contain only \code{id}, \code{key} and \code{definition\_ref}; the compiler verifies and lowers the referenced fields to \code{Cell48}. The state-orbit example uses this definition-driven form for all ten cells.

\subsection{State64}
The mutable state contains sixteen 32-bit words:
\begin{equation}
q_n=(\rho,\theta,X,\phi,\dot\rho,\dot\theta,\dot X,\dot\phi,o,s_h,b,i,\ell,y,r,\eta).
\end{equation}
Here $o$ is orientation, $s_h$ is sheet, $b$ is the branch bit, $i$ is the cell index, $\ell$ is lineage, $y$ is output, $r$ is the last relation residual and $\eta$ is the status word. The dot notation names stored first differences; it does not imply that the integer runtime is integrating an untyped physical force.

\subsection{Cell48}
Each immutable cell is
\begin{equation}
c_i=(K_{hi},K_{lo},op,flags,a_0,a_1,a_2,a_3,next_0,next_1,payload,aux).
\end{equation}
The cell is both LUT data and executable operator. The two successor indices make the one-bit branch explicit. No pointer size, heap object or vendor-specific instruction appears in the format.

\subsection{Continuous source chart and compiled integer chart}
The source chart is
\begin{equation}
\rho=\ln(r/r_0),\qquad \theta=\operatorname{atan2}(y,x),\qquad r=r_0e^\rho.

Its planar metric and Jacobian are
\begin{equation}
ds^2=r^2(d\rho^2+d\theta^2),

J=r\begin{bmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{bmatrix}.

A compiler quantizes the declared chart into integer coordinates. The hot TOMAGI transition never calls $\log$, $\exp$, $\sin$ or $\cos$.

\section{Literal SDF-zero as the memory architecture}

\begin{literalbox}
Let $D_K$ be the finite set of keys carried by the compiled LUT. TOMAGI defines
\begin{equation}
Z_D(K)=
\begin{cases}
0,&K\in D_K,\\
\bot,&K\notin D_K.
\end{cases}
\end{equation}
Every definable cell is therefore literally on the zero level. An address outside the domain is undefined, not a positive or negative distance sample.
\end{literalbox}

This definition resolves the source request to treat SDF-zero as a general operator inside the LUT rather than as an external apex-only boundary. Data storage and geometric/topological definition coincide at the cell. The 
\code{SDF0} opcode sets residual zero, marks the zero status and emits branch one. It does not contract the state toward a surface.

The complement value $\bot$ is essential. Assigning numerical distance zero to every 64-bit word would erase the distinction between a program cell and a non-address. TOMAGI instead gives the source phrase ``SDF 0 on all definable points or bits'' its literal finite meaning.

\section{The one-bit parity/jitter operator}

\subsection{Exact bit derivation}
Given program seed $s$, key words $(K_h,K_l)$, timeline tick $X$ and cell salt $a$, define
\begin{align}
h_n&=\operatorname{mix32}(s\oplus K_h\oplus\operatorname{rotl}_{32}(K_l,13)\oplus X\oplus a),\\
j_n&=\operatorname{popcount}(h_n)\bmod2,\\
\sigma_n&=2j_n-1\in\{-1,+1\}.
\end{align}
The specified mixer is
\begin{lstlisting}
x ^= x >> 16;
x *= 0x7feb352d;
x ^= x >> 15;
x *= 0x846ca68b;
x ^= x >> 16;
\end{lstlisting}
with all operations in $\uword$.

For a selected state field $z$ and cell amplitude $A$,
\begin{equation}
z' = z + \sigma_n A,\qquad b'=j_n.
\end{equation}
Thus one bit performs two literal roles: bipolar local jitter and branch selection. Because every input to the bit is declared, repeated execution is reproducible.

\subsection{What parity does not do}
Parity is not interpreted as a health flag. Even and odd states are both ordinary program states. There is no hidden statement that odd means failure, no Hamming-code upgrade and no automatic return-to-boundary force. A program may route an odd branch to any cell its author declared.

\section{Kinematic change-of-change inside the LUT}

\subsection{Integer second-order update}
Collect the four coordinates and first differences as
\begin{equation}
p_n=(\rho_n,\theta_n,X_n,\phi_n),\qquad v_n=(\dot\rho_n,\dot\theta_n,\dot X_n,\dot\phi_n).
\end{equation}
A \code{KIN2} cell stores
\begin{equation}
a_i=(a_0,a_1,a_2,a_3).
\end{equation}
The transition is
\begin{align}
v_{n+1}&=\operatorname{wrap}_{32}(v_n+a_i),\\
p_{n+1}&=\operatorname{wrap}_{32}(p_n+v_{n+1}).
\end{align}
This ordering is explicit and shared by all backends. The fourth acceleration component $a_3$ is the literal runtime $\Delta^2\phi$ operator requested in the source sequence.

\subsection{Continuous log-polar interpretation}
When a real-valued geometric source is compiled, SCLP supplies
\begin{align}
v&=r(\dot\rho e_r+\dot\theta e_\theta),\\
a&=r\left[(\ddot\rho+\dot\rho^2-\dot\theta^2)e_r+(\ddot\theta+2\dot\rho\dot\theta)e_\theta\right].
\end{align}
TOMAGI treats these as host-side parameterization equations. The compiled cell contains the integer change-of-change used during execution.

\section{Lower-case phi and the zero-based timeline}

\subsection{Symbol separation}
The source corpus overloads $T$, time, torque and $\phi/\Phi$. TOMAGI imposes one contract:
\begin{itemize}
\item $T_c$ denotes cone slant length in a geometric definition;
\item $X$ denotes the zero-based modular timeline tick;
\item lower-case $\phi\in\mathbb{Z}/2^{12}\mathbb{Z}$ denotes phase/hoop/hinge state;
\item capital $\Phi=(1+\sqrt5)/2$ is optional compile-time metadata and never the runtime phase.
\end{itemize}

\subsection{Timeline update}
For increment $d_X$,
\begin{equation}
raw=X+d_X,
\quad
w=\left\lfloor\frac{raw}{2^{14}}\right\rfloor,
\quad
X'=raw-w2^{14},
\quad
b'=w\bmod2.
\end{equation}
The human ordinal is $X+1$. This is the exact interpretation of the source observation that offset 35 is the 36th position: the address remains zero based.

\subsection{Lower-case phi update}
The \code{PHI} opcode applies the analogous modulo-$2^{12}$ update. It may expose wrap parity or the half-circle bit as branch state. An odd wrap may flip orientation when the cell requests it. This makes lower-case $\phi$ an actual stateful hinge rather than a decorative symbol.

\section{Topological transport}

\subsection{Reflective Klein profile}
Let
\begin{equation}
w=\left\lfloor\frac{\rho}{2^{20}}\right\rfloor,
\qquad
\rho'=\rho-w2^{20}.
\end{equation}
When $w$ is odd, the reflective profile applies
\begin{align}
\theta'&=2^{17}-\theta\pmod{2^{18}},\\
\phi'&=-\phi\pmod{2^{12}},\\
o'&=o\oplus1,\\
s_h'&=s_h\oplus f_s,\\
b'&=1.
\end{align}
The angular reflection reverses orientation. On an even wrap, the corresponding fields remain unchanged and $b'=0$.

The literal source formula is preserved under a flag:

\theta'=\theta+2^{17}\pmod{2^{18}},\qquad \phi'=-\phi,\qquad o'=o\oplus1.
\end{equation}
It is a twisted state bundle but not silently called the reflective base quotient. Keeping both maps makes source fidelity and topology precise at once.

\section{Cone, circle, sphere and overlap relations}

\subsection{Finite cone source geometry}
A right circular cone is compiled from slant length $T_c>0$ and half-angle $0<\alpha<\pi/2$:
\begin{equation}
h=T_c\cos\alpha,\qquad R=T_c\sin\alpha.
\end{equation}
The exact Euclidean primitive can be evaluated by distance to its filled meridian triangle. TOMAGI's portable cell uses a quantized log-polar support relation instead of carrying floating-point primitive evaluation in every backend.

\subsection{Packed cone relation}
Let $\bar\rho$ and $\bar\theta$ be normalized state coordinates and $\delta_N$ the shortest cyclic difference. A \code{CONE} cell evaluates
\begin{equation}
r_C=\max\{\rho_{min}-\bar\rho,\;\bar\rho-\rho_{max},\;|\delta_{2^{18}}(\bar\theta,\theta_0)|-|\alpha_q|\}.
\end{equation}
It sets $b=1$ precisely when $r_C\le0$.

\subsection{Sphere or shell relation}
A \code{SPHERE} cell evaluates
\begin{equation}
r_S=\max\{|\bar\rho-\rho_0|-|d_\rho|,\;|\delta_{2^{12}}(\bar\phi,\phi_0)|-|d_\phi|\}.
\end{equation}
A negative $d_\phi$ disables the phase component and yields a pure radial shell.

\subsection{Projection semantics}
The side-view pyramid, circle and sphere are symbolic projection tokens. A cone viewed through the triangular profile may emit \code{PYRA}; its axial radial profile may emit \code{CIRC}; a spherical support may emit a sphere token. \code{PROJECT} and \code{EMIT} make the selected token and replay state authoritative. File representations are separate definition programs: the shipped 2D source affinely maps emitted $(\theta,\rho)$ fields to an SVG polyline, while the 3D source maps $(\rho,\theta,\phi)$ to OBJ vertices and declares an ordered open line. Neither file syntax nor mapping is built into an opcode or the generic materialization host.

\subsection{Overlap lens}
The source's slight overlap is the exact shared domain
\begin{equation}
L=A\cap B.
\end{equation}
It can be compiled as conjunction, join eligibility or a connector hinge. TOMAGI does not assign an unstated physical energy meaning to the lens.

\section{Radix routing, hinges and the L-system}

\subsection{Radix branch}
\code{RADIX(k)} selects bit $k$ from the canonical key. Repeated tests create a radix-2 trie over the packed state. The operation refines an address prefix; it does not divide the decoded coordinates by two.

\subsection{Hinge}
The compiled hinge is
\begin{equation}
H=(state,M_0,M_1,invariant\ metadata).
\end{equation}
$M_0$ is identity. If $b=1$, $M_1$ adds the cell's four arguments to $(\rho,\theta,X,\phi)$ and optionally flips orientation and sheet. Hinges compose in stored order and are not assumed to commute.

This interface covers geometric rotation after quantization, parity-selected routing, a zero-magnitude connector such as Dutch \emph{en}, and the split-$\phi$/double-D fold when the definition explicitly declares those semantics.

\subsection{L-system transform}
For turn quantum $\tau$ and dyadic shift $d$,
\begin{align}
\chi&=(-1)^o,\\
s_b&=2b-1,\\
\phi'&=\phi+\chi s_b\tau\pmod{2^{12}},\\
v'&=\operatorname{trunc}_0(v/2^d).
\end{align}
This is the one-step executable condensation of
\begin{equation}
F(T)\Rightarrow F(T/2)[\,\pm\phi\,F(T/2)\,].
\end{equation}
The finite program graph, not a hidden recursion manager, determines the actual sequence of steps.

\section{Transition, output and lineage}

After an opcode, periodic fields are normalized and lineage is updated:
\begin{equation}
\ell'=\operatorname{mix32}(\ell\oplus payload\oplus aux\oplus K_h\oplus\operatorname{rotl}_{32}(K_l,7)\oplus b\oplus i).
\end{equation}
The next cell is
\begin{equation}
i'=\begin{cases}next_0,&b=0,\\next_1,&b=1.\end{cases}
\end{equation}
A flagged cell may instead re-key the normalized state and binary-search the sorted LUT. A miss is observable in status and falls through to the declared successor; no replacement state is invented.

\code{PROJECT} writes a token and continues. \code{EMIT} writes a token and marks an output; its low flag bit may terminate. \code{HALT} terminates without changing the current token. A trace records the exact operator order and every resulting state field. The generic representation pipeline first uses \code{authenticated\_trace} to hash-check the relative source/program/trace files, recompile the source and replay the trace. It then applies \code{select\_records}, integer-affine \code{project\_fields} and UTF-8 \code{format\_records}. The compiler lowers the resulting bytes to sequential \code{EMIT} cells.

The later \code{materialize} host merely executes that byte program and concatenates each declared one-to-four-byte big-endian payload. It does not re-open the source trace, project fields, format records or recognize SVG, OBJ or CSV.

The first-party artifact path is therefore
\begin{equation}
\begin{aligned}
\text{orbit definitions}&\longrightarrow\text{authenticated State64 trace}\\
&\longrightarrow\text{formatted bytes}\longrightarrow\text{EMIT-only \texttt{.tmg}}\\
&\longrightarrow\text{SVG, OBJ or CSV bytes + manifest}.
\end{aligned}
\end{equation}

\section{Deterministic substitution for AI}

\begin{definitionbox}
A task is TOMAGI-compilable when its input has a finite typed encoding; its facts and transformations can be expressed as finite definitions, relations or branch rules; and its answer has a finite output representation. Its deterministic inference function is
\begin{equation}
answer=\operatorname{Exec}(\operatorname{Compile}(D,R),\operatorname{Encode}(x),m).output.
\end{equation}
\end{definitionbox}

There are no learned weights, embeddings, sampling temperatures, confidence scores or hidden random state in this execution. The one-bit sequence is a pure function of explicit inputs. This makes TOMAGI suitable for compiled classification, finite-state planning, procedural generation, relation queries, spatial routing, signal-state transforms and symbolic rule systems.

The distinction from a learned model is exact. A learned model may statistically generalize beyond its training examples. TOMAGI evaluates what has been made literal. New knowledge enters by adding or compiling definitions and cells, not by changing opaque weights.

\section{Execution backends and the generic host boundary}

\subsection{Python oracle}
The dependency-free Python package supplies canonical JSON, definition hash verification, topological dependency ordering, the two key codecs, binary serialization, the exact step function and a JSON trace CLI. It is the readable reference semantics.

\subsection{C99 evaluator}
The C implementation reads little-endian bytes explicitly and does not rely on compiler structure packing. It defines floor division, two's-complement conversion, modular addition and cyclic differences directly. The same \code{.tmg} file is therefore portable across ordinary CPU architectures.

\subsection{Definition evaluation and byte materialization}
The Python compiler evaluates the generic kinds \code{authenticated\_trace}, \code{select\_records}, \code{project\_fields} and \code{format\_records}. Authentication proves the declared hashes, source-definition anchors, source-to-program compilation, full replay trace and final state. Selection, integer affine maps, file framing and record templates remain content-addressed definition data. The evaluated bytes are compiled to ordinary \code{EMIT} cells.

\code{tomagi materialize} is deliberately smaller: it runs a \code{.tmg}, selects executed \code{EMIT} cells and concatenates their length-delimited big-endian payload bytes under profile \code{tomagi-emit-bytes-be-v1}. Its manifest records hashes, byte/chunk counts, steps and final state. No host branch names a file format, geometric primitive or dimension.

\subsection{GPU kernels}
The GLSL 4.50, WGSL and OpenCL C kernels use the same three logical inputs:
\begin{enumerate}
\item read-write \code{State64[]} array;
\item read-only sorted \code{Cell48[]} array;
\item parameters $($state count, cell count, seed, reserved$)$.
\end{enumerate}
One invocation executes one transition for one independent state. Repeated dispatches advance the query horizon. The kernels require ordinary 32-bit integer storage, shifts, addition, comparison and bit count. They make no vendor, tensor-core, ray-tracing-core or floating-point performance assumption.

\begin{evidencebox}
The current Windows validation ran 62 Python tests and authenticated the three representation DAGs and their exact bytes. Python/C comparisons were not run because the available C evaluator is a Linux ELF executable. GLSL and WGSL received structural source checks; Clang and a physical GPU dispatch runtime were unavailable, so OpenCL syntax and device execution are not claimed.
\end{evidencebox}

\section{Normative no-failsafe profile}

\begin{nofailsafebox}
TOMAGI 1.0 does not include the following earlier-draft layers in its transition algebra:
\begin{center}
\begin{tabularx}{0.94\textwidth}{@{}YY@{}}
\textbullet\ jitter interval/event-margin guard & \textbullet\ Hamming or ECC correction\\
\textbullet\ boundary restoration/contraction force & \textbullet\ damping or emergency retreat\\
\textbullet\ confidence threshold & \textbullet\ safe mode or watchdog route\\
\textbullet\ dynamic allocation safety ring & \textbullet\ claims-ledger kill criterion\\
\end{tabularx}
\end{center}
Parity is an ordinary branch. SDF0 returns zero at every defined cell. No hidden policy changes those results.
\end{nofailsafebox}

A finite file still has a grammar: record sizes, version, unique keys, resolvable references and in-range successors define whether bytes can be parsed as a TOMAGI program. These are syntax and identity rules, not a runtime correction mechanism.

\section{Final engine definition}

\begin{definitionbox}
\textbf{TOMAGI 1.0 is a finite, content-addressed, deterministic operator machine in which a 20/18/14/12 log-polar key selects a literal SDF-zero LUT cell; a parity-of-mixed-word one-bit operator produces signed jitter and a branch; integer second-order kinematics advances log-radius, angle, zero-based time and lower-case phi; reflective Klein or half-turn maps transport orientation and sheet; branch-indexed radix/hinge routing precedes L-system grammar and cone/sphere/overlap classification; projection and emission then return replayable \code{State64} answers with lineage. Branch-indexed successors serialize non-commutative composition. The same 64-byte state and 48-byte cell definitions map to the supplied Python, C, GLSL, WGSL and OpenCL implementations. Generic content-addressed definitions can authenticate traces, select and affinely map integer fields, format records and compile the bytes to \code{EMIT} cells; the host evaluates those definitions, while materialization only replays the bytes and assigns no SVG, OBJ, CSV or dimensional meaning.}
\end{definitionbox}

For compiled domains, this is the deterministic substitute for AI: definitions replace weights, relation cells replace opaque activations, the one-bit route replaces stochastic sampling, and the trace exposes every transition that produced the answer.
