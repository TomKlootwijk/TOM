# TOM World & Query Kernel 0.3

## Exact rational interval relations, certified crossings, simultaneous event sets, and deterministic event transitions

**Normative identifier:** `TOM-WORLD-QUERY-KERNEL-0.3`  
**World schema:** `TOM-WORLD-INTERVAL-EVENTS-0.3`  
**Underlying execution ABI:** TOMAGI 1.0  
**Canonical root:** `TOM_seed_genome_2026-09-01.txt`  
**Release date:** 2026-09-01

## 1. Status

This document defines the 0.3 interval-event extension to the TOM World & Query Kernel. It continues the 0.1 persistent query kernel and the 0.2 immutable-index/checkpoint kernel without changing the TOMAGI machine.

The terms **MUST**, **MUST NOT**, **SHALL**, **SHOULD**, and **MAY** are normative. A conformance claim is limited to the finite arithmetic, trajectory, relation, support, compatibility, event, and transition profiles specified here.

The 0.3 release does not claim a general continuous differential-equation solver. It certifies roots of continuous expressions over exact rational affine trajectories. General expressions built from addition, subtraction, and multiplication can receive sign-change brackets; exact simultaneous grouping is restricted to roots with an exact canonical rational time.

## 2. Purpose

The previous kernel answered exact discrete queries and accelerated them with immutable indexes and exact checkpoints. The next missing substrate capability was to represent and certify events that occur between integer TOMAGI ticks.

This release supplies:

```text
exact rational values
-> closed rational intervals
-> typed continuous relation expressions
-> exact affine trajectory interpolation
-> endpoint and interval residual evaluation
-> sign-change existence certificates
-> derivative-interval uniqueness certificates
-> exact affine root times where available
-> support and compatibility gates
-> simultaneous event sets
-> deterministic event order
-> conflict-checked atomic transition merge
-> comparison with an independent trusted baseline
```

## 3. Non-change to TOMAGI

TOMAGI ABI 1.0 remains frozen:

| Item | Value |
|---|---:|
| Binary header | 128 bytes |
| `State64` | 64 bytes |
| `Cell48` | 48 bytes |
| Opcode count | 16 |
| Version word | `0x00010000` |

No 0.3 relation, interval, or event-set concept is inserted as a hidden hot opcode. The interval layer is a query service above deterministic TOMAGI trajectories. Integer trajectory anchors can be generated by a `.tmg` program and checked against the rational interpolation.

## 4. Canonical rational numbers

A rational number is the pair:

```json
{"num": integer, "den": positive-integer}
```

The canonical representation satisfies:

```text
den > 0
gcd(abs(num), den) = 1
num = 0 implies den = 1
```

All arithmetic is exact. There is no binary floating-point conversion in the certified path.

For rational values `a/b` and `c/d`:

```text
addition       (ad + cb) / bd
subtraction    (ad - cb) / bd
multiplication ac / bd
division       ad / bc, c != 0
comparison     ad ? cb
```

Every result is reduced and normalized immediately.

## 5. Closed intervals

A closed interval is:

```json
{
  "lower": {"num": ..., "den": ...},
  "upper": {"num": ..., "den": ...}
}
```

with `lower <= upper`.

For intervals `A=[a0,a1]` and `B=[b0,b1]`:

```text
A + B = [a0+b0, a1+b1]
A - B = [a0-b1, a1-b0]
-A    = [-a1,-a0]
A * B = hull(a0b0, a0b1, a1b0, a1b1)
1/A   = [1/a1,1/a0], only when 0 is not in A
A / B = A * (1/B), only when 0 is not in B
```

Because operands are exact rationals, the resulting bounds are exact for these operations. No rounding mode or outward floating-point approximation is required.

The sign classification is one of:

```text
negative
positive
zero
nonnegative
nonpositive
straddles-zero
```

## 6. Affine rational trajectory

The 0.3 normative trajectory profile is:

```json
{
  "kind": "affine-rational-trajectory",
  "domain": {"lower": Q, "upper": Q},
  "fields": {
    "field-name": {"initial": Q, "rate": Q}
  }
}
```

For field `x`:

```text
x(t) = initial_x + rate_x * t
```

The point state at rational time `t` is the exact mapping of every field to `x(t)`. The interval value over `[t0,t1]` is the exact hull of `x(t0)` and `x(t1)`.

A trajectory MAY identify a TOMAGI source program. Where it does, validation SHOULD compare every integer anchor in the declared domain against the actual TOMAGI trace. The supplied fixture uses one `KIN2` cell with constant `vrho=2` and `vtick=1`; its integer anchors satisfy `rho=2*t` and `State64.tick=t`.

## 7. Continuous relation expression language

A relation expression is a finite tree containing:

| Operation | Meaning |
|---|---|
| `const` | Exact rational constant |
| `field` | Named affine trajectory field |
| `time` | Independent rational time variable |
| `neg` | Arithmetic negation |
| `add` | Binary addition |
| `sub` | Binary subtraction |
| `mul` | Binary multiplication |

The expression is continuous because it is a finite polynomial composition over affine continuous fields. Unsupported operations reject.

### 7.1 Point evaluation

At time `t`, every leaf is an exact rational and the expression evaluates recursively to an exact rational residual `R(t)`.

### 7.2 Interval and derivative evaluation

Each expression is evaluated as a dual interval:

```text
(value interval, derivative interval)
```

Rules include:

```text
D(const c) = ([c,c], [0,0])
D(time)    = ([t0,t1], [1,1])
D(field x) = (range(x,[t0,t1]), [rate_x,rate_x])
D(a+b)     = (Va+Vb, Da+Db)
D(a-b)     = (Va-Vb, Da-Db)
D(a*b)     = (Va*Vb, Da*Vb + Va*Db)
```

The derivative interval is used only for a sound monotonicity test. If it excludes zero, the relation is strictly monotone on the bracket.

### 7.3 Affine extraction

When the expression is affine in global time, the evaluator derives exact coefficients:

```text
R(t) = slope * t + intercept
```

Multiplication remains affine only when one operand has zero time slope. If `slope != 0`, the exact root is:

```text
t* = -intercept / slope
```

## 8. Relation record

A normative relation contains:

```text
id

relation_interface = SDF0@Def
domain = affine-rational-trajectory
codomain = exact-rational-residual
zero_locus
priority
expression
support_id
compatibility_id
active_time
event_id
transition
provenance

```

The relation is content-addressed by canonical JSON excluding the top-level `content_hash` field.

`SDF0@Def` remains a definition-level typed zero-relation interface. It does not change runtime TOMAGI opcode 6 and does not imply that all data are numerically zero.

## 9. Support and compatibility

### 9.1 Interval support

An interval support declares bounds by field. An exact root state is accepted only when every constrained field lies inside its closed bound.

For a root represented only by a refined bracket, support is certified only when the complete state interval is a subset of every declared bound.

### 9.2 Field-equality compatibility

A compatibility record declares exact rational field values. An exact root state is compatible only when every constrained field equals its declared value.

For a nonpoint bracket, equality compatibility is certified only when each constrained state interval is itself a point equal to the required value. This prevents a broad interval from being accepted merely because it contains the desired value.

## 10. Crossing certification

Given relation `R` and bracket `[a,b]`:

1. The bracket MUST lie inside both the trajectory domain and relation active interval.
2. Compute exact endpoint residuals `fa=R(a)` and `fb=R(b)`.
3. Compute the residual interval and derivative interval over `[a,b]`.
4. Existence is certified when:
   - `fa = 0`; or
   - `fb = 0`; or
   - `sign(fa) != sign(fb)` and neither is zero.
5. If the expression is affine and its slope is nonzero, compute the exact root and require it inside the bracket.
6. Otherwise, on a sign change, apply a declared number of exact rational bisections while preserving an opposite-sign or exact-zero invariant.
7. Uniqueness is certified only when existence is certified and the derivative interval excludes zero.
8. Evaluate support and compatibility at the exact root, or conservatively over the refined interval when no exact root is known.
9. Accept only when existence, support, and compatibility all pass.

A zero-containing residual interval alone is **not** treated as an existence proof. This avoids the classic interval overestimation error.

The certificate records:

```text
world and relation hashes
original bracket
endpoint residuals
residual interval
derivative interval
existence basis
uniqueness basis
exact root, if known
refined bracket
bisection count
support result
compatibility result
root state
ordering key
content hash
```

## 11. Event enumeration

`events(start,end)` partitions the requested interval into unit rational brackets aligned to integer ticks. Every relation is certified on every intersecting bracket. Accepted relation/root pairs are deduplicated so an exact root on an integer boundary is not returned twice.

Accepted events are ordered by:

```text
(root_time, priority, relation_id, event_id, relation_hash)
```

Exact rational comparison is used for time. String components are compared by their canonical Unicode code-point order as represented in JSON strings.

## 12. Simultaneous event sets

`next_event_set(after,before)` returns the earliest accepted exact root strictly after `after`, unless `include_after=true`.

All accepted relations with the exact same reduced rational root are simultaneous. The event set contains:

```text
event_time
event_count
event_order
relation_order
ordering_rule
individual crossing certificates
content_hash
```

The 0.3 release does not merge merely overlapping nonexact brackets into a simultaneous set. That would overclaim equality of event time. Nonexact brackets remain individual certified candidates until a later profile defines set-valued temporal equivalence.

## 13. Atomic simultaneous transition

Every relation may declare zero or more operations:

```json
{"field": "name", "mode": "set|add|xor", "value": Q}
```

All operations read the common pre-event state. They are grouped by field.

| Mode | Merge rule |
|---|---|
| `set` | All simultaneous values MUST be exactly equal; otherwise reject. |
| `add` | Values sum exactly and are added once to the pre-state. |
| `xor` | Integer values XOR together and are XORed once with an integer pre-state. |
| mixed modes on one field | Reject. |

There is no implicit last-writer-wins rule. Event ordering is recorded for audit, but conflict freedom does not depend on host iteration order.

The transition certificate records pre-state, contributors, merged operation per field, post-state, merge policy, event-set hash, and its own content hash.

## 14. Independent trusted baseline

The supplied baseline implementation deliberately does not import the 0.3 rational, interval, expression, or solver classes. It uses Python's independent `fractions.Fraction` type and a separate affine-expression linearizer.

For each affine relation it derives `slope` and `intercept`, computes `-intercept/slope`, applies active-time/support/compatibility gates, and sorts by the normative event key. The semantic event list MUST equal the interval solver's exact-root event list for the fixture.

This is an implementation-level differential check. It is not a proof that arbitrary continuous mathematics has been solved.

## 15. Reference fixture

The fixture trajectory is:

```text
x(t)       = 2t
clock(t)   = t
mode(t)    = 1
counter(t) = 0
output(t)  = 0
0 <= t <= 10
```

Three accepted relations have the same root:

```text
time - 5/2     = 0
3*x - 15       = 0
x - 5          = 0
```

Their exact root is `t=5/2`. Priorities and IDs produce this order:

```text
event:time-five-halves:set-output
event:triple-x:add-two
event:x-five:add-one
```

The common pre-state includes `x=5`, `clock=5/2`, `counter=0`, and `output=0`. The merged transition yields:

```text
counter = 3
output  = 25
```

A fourth accepted relation `x-10=0` occurs later at `t=5`. Additional fixture relations demonstrate inactive-time, outside-support, and compatibility rejection.

## 16. Required rejection conditions

A conforming 0.3 implementation MUST reject or return a nonaccepted certificate for:

- zero rational denominator;
- noncanonical or inverted interval bounds;
- world, trajectory, support, compatibility, or relation hash mismatch;
- duplicate IDs;
- missing support or compatibility references;
- unsupported expression operation or malformed arity;
- field absent from the trajectory;
- bracket outside trajectory or active domain;
- refinement request above the declared maximum;
- zero-containing interval without endpoint sign evidence, when neither endpoint is exactly zero;
- support failure;
- compatibility failure;
- nonexact root requested for exact simultaneous grouping;
- mixed simultaneous transition modes on one field;
- unequal simultaneous `set` values;
- rational `xor` operand with denominator other than one; or
- event-set relation IDs not present in the selected world.

## 17. Resource bounds

The fixture profile sets:

```text
refine_steps      = 24
max_refine_steps  = 128
```

Expression depth is bounded by the implementation's validation limit of 64. Event enumeration is finite because the trajectory domain, query interval, relation list, expression trees, and bisection count are finite.

A future large-world interval index may reduce candidate relations before certification, but MUST return the same semantic certificates as exhaustive relation enumeration.

## 18. Determinism theorem

For fixed canonical world record `W`, exact rational query bounds `a,b`, and refinement count `n`, any conforming implementation produces equal:

```text
rational normal forms
interval arithmetic bounds
point residuals
interval residuals
derivative intervals
certified root status
exact affine root time
support and compatibility result
event order
simultaneous event membership
conflict result
merged post-state
canonical certificate bytes
content hashes
```

The result follows because all values are reduced integers, every expression is a finite ordered tree, all iteration order is explicit, bisection midpoints are exact rationals, sorting uses a total key, and transition merging is defined per field without ambient map order.

## 19. Validation requirements

A 0.3 release MUST demonstrate:

1. all previous TOMAGI and world-kernel tests still pass;
2. TOMAGI ABI sizes remain 128/64/48;
3. the reference `.tmg` has equal Python/C full traces;
4. every integer reference anchor equals the affine trajectory;
5. the `x-5` bracket `[2,3]` has residuals `-1,+1`, root `5/2`, and derivative interval `[2,2]`;
6. the earliest event set contains exactly three events in the normative order;
7. simultaneous transition yields `counter=3` and `output=25`;
8. the later event occurs at `t=5`;
9. inactive, unsupported, and incompatible candidates are rejected;
10. unequal simultaneous sets are rejected;
11. the independent `Fraction` baseline event list equals the solver event list;
12. schemas and all content hashes verify;
13. generated certificates are deterministic; and
14. a generated-output-free clean copy reproduces the recorded 0.3 boundaries.

## 20. Evidence boundary and next milestone

This release establishes exact rational interval-event semantics for affine trajectories and polynomial relation expressions. It does not yet establish:

- interval integration of nonlinear dynamics;
- arbitrary transcendental interval functions;
- validated ODE enclosures;
- event clusters whose exact times are not resolved;
- causal resolution of mutually modifying simultaneous relations;
- interval indexes over the 10,000-record store;
- autonomous learning, planning, or AGI.

The next kernel milestone is **0.4: validated piecewise dynamics and event transactions**. It should add piecewise-affine/validated-step trajectories, interval-index pruning, event-set transaction commits into the persistent world, post-event trajectory continuation, and trusted comparison against independently generated piecewise trajectories.
